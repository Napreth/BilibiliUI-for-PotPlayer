# 字幕与弹幕自动分类

加载时先解析事件，优先核对转换器内嵌的原始数据，其次识别已知生成器的样式约定，最后结合高级表现和通用时空统计分类。文件扩展名不决定用途；手动分类仍保存在原来的 `CaptionOptions.Classes` 中，自动评分单独保留，不覆盖用户选择。

事件保留源时间、原始内容、来源／声明、样式、Layer、对齐、归一化位置、运动、特效标记及 `DurationInferred`。ASS 读取 PlayRes 与样式、事件边距和覆盖标签；用字号、行数和对齐估计文本区域中心，归一化垂直分布。该估计用于分类，不是 libass 的完整字体排版。

ASS 头部包含 `; Script generated by DanmakuFactory v版本号` 签名时，启用该转换器的样式规则：`R2L`、`L2R`、`TOP`、`BTM` 分别对应 B 站 Mode 1、6、5、4，`SP` 对应高级表现。已知样式无需统计样本门槛；静态或单一水平匀速移动的 `SP` 仍进入高级组。普通样式若包含实际高级特效或无法解析的关键结构，仍分别进入高级或存疑组。

转换器分类标记与协议标记独立，标准 ASS 的 `SP` 仍可由 libass 播放。未知样式单独走通用分析，不因同文件的签名而直接视为弹幕，也不影响已确认样式的分类。没有签名时不凭 `SP` 等名称套用转换器规则。拆分保留原始样式、Layer、时间、事件顺序与 ASS 指令；渲染策略仍由分类后的既有链路处理。DF 的规则依据项目锁定的[写入及反读实现](https://github.com/hihkm/DanmakuFactory/blob/3813e93b13b087e95901d1822baf9c3540e3f3f6/src/AssFile/AssFile.c)。

### dan-any 的 Raw 与生成器识别

兼容 `dan-any-ext-ass` v2 的 `;RawConf:`／`;RawPb:`，以及 dan-any v1／biliy 的 `;Raw:` JSON。支持 gzip、brotli、zstd 与 Base64／Base16384；上游实际把 Base16384 编码标签写为 `base18384`，读取器兼容该拼写及 `base16384`。省略压缩与编码字段的旧版 Raw 按 gzip／Base64 处理，重复、缺失、损坏或不支持的字段回退到 ASS 分析，不把来源置为读取失败。只有 Script Info 或 Events 中独立的元数据注释行参与读取。

新格式按 DanUni Protobuf 的字段号读取时间、模式、字号、颜色、权重、平台及扩展，不读取发送者或弹幕标识。统一模式 Normal／Bottom／Top／Reverse 对应 B 站 1／4／5／6；Ext 再按 `extra.bili.adv/code/bas` 或保留的原始 mode 确认 7／8／9。旧版 JSON 的秒时间和 biliy 的 RGB、type、fontSizeType 单独适配，不与新格式的毫秒时间和模式枚举混用。

Raw 保存的是转换前数据，可能包含已被合并、过滤或未输出的条目，不能按 ASS 行号配对。读取器按原始内容经过生成器转义后的文本与输出时间建立索引，恢复匹配事件的类型和权重；同一文本与时间存在相互冲突的原始类型时保留存疑。对具有生成器签名的文件，还核对该版本已确认的单数字厘秒输出格式。匹配不改 ASS 原有时间或指令；未输出的 Raw 记录只作为来源数据保存，不重新加入播放。

缺少有效 Raw 时，依据头部 `Original Script` 中的正式来源标记识别 dan-any v2、dan-any v1 和 biliy。只有该来源下的 `F数字` 样式使用普通弹幕约定；未知来源不能只凭 `F1` 认定为弹幕，未知样式继续通用分析。实际高级特效和无法解析的关键结构仍优先进入高级或存疑组。

Raw 恢复的是来源和管理类别，播放仍使用文件中已有的 ASS 表现。Raw 指向高级模式时不会把标准 ASS 标成不可渲染协议；也不会执行 Raw 中的 Mode 8／BAS 载荷，或承诺恢复生成器已经降级、丢弃的动画。独立 XML／JSON 的 Mode 7 继续由 DF 转换；未转换的 Mode 8／9 沿用禁用规则。

实现为独立 C# 文件／协议读取器，不引入 UniDB、数据库或 JS 引擎。解码内容与条目数分别限制在 32 MiB／100000，Raw 配置限制在 1 MiB，JSON 深度限制为 32；原生 zstd／brotli 解码器另有 64 MiB 分配预算。对应来源为 [Raw 写入和读取](https://github.com/ani-uni/dan-any-ext-ass/blob/a6779937a01ac6096df9f984d0d37b00aea1dbf9/src/ass-gen/ass/raw.ts)、[ASS 文本和时间输出](https://github.com/ani-uni/dan-any-ext-ass/blob/a6779937a01ac6096df9f984d0d37b00aea1dbf9/src/ass-gen/ass/dialogue.ts)、[DanUni 协议定义](https://github.com/ani-uni/dan-any/blob/c24e97a1856fda4c9688951eb324e13f33644f48/src/utils/proto/src/danuni/danmaku/v1/danmaku.proto) 和 [B 站模式适配](https://github.com/ani-uni/dan-any/blob/c24e97a1856fda4c9688951eb324e13f33644f48/src/adapters/bili/grpc.ts)。版权和第三方解压库说明见 [LICENSES](../../LICENSES/README.md)。

### 通用分析

第一阶段把 Mode 7–9、明确的 JSON 高级类型、有效淡入淡出／卡拉 OK／样式动画、非水平运动、带静止阶段的运动、矢量绘图和特殊裁剪拆入高级组。水平匀速正向或反向滚动属于普通运动。`\fad(0,0)` 和属性不变的变换不会触发高级；无法可靠解析的关键结构进入存疑组。高级事件保留原始数据和计数，禁止通过手动改分类绕过其结构限制。标准 ASS／SSA 特效由 libass 读取原始事件渲染；加载阶段可将 Mode 7 转为 ASS，转换后仍属高级组。Mode 8／9 及其他未支持的专用协议保持禁用，不执行脚本。转换不参与分类评分，细节见 [弹幕转换](../danmaku-conversion.md)。ASS 标签语义依据 [Aegisub 官方说明](https://aegisub.org/docs/latest/ass_tags/)。

第二阶段对普通组计算：

- O2／O3：扫描线按半开区间累计至少 2／3 条事件同时显示的时间比例。
- B3：开始时间 ±0.5 秒邻域内至少 3 条事件的比例，排序后双指针计算。
- Q：相邻事件依次显示的比例，容差 0.05 秒。
- M：已知运动中水平滚动的比例。
- Hy：12 个归一化垂直分区的熵。
- Bottom：已知静态事件位于底部 25% 且居中显示的比例。

弹幕证据权重为 M=3、O3=2.5、B3=2、Hy=1；字幕证据为 Q=1.5、Bottom=1.5，分别按可用数据可靠度归一化。O2 记录用于诊断，不重复加权。推断时长不参与重叠与连续性；水平滚动降低 Q 的字幕证据可靠度；缺失空间信息不计空间证据。渲染速度、字号等用户选项不进入识别。

差值 D−S 达到 ±0.35 才自动分类。没有可靠来源声明时至少需要 8 条事件和 2 个有效特征；两边证据均较强、字幕时长证据不足、极稀疏或差值不够时保持存疑。字幕判定还要求至少 80% 事件有源时长，且显示时长相对时间跨度有足够覆盖。阈值是初版启发式，不代表训练出的准确率。

只在样式／Layer／运动子组各有至少 8 条事件、且分别稳定支持字幕和弹幕时，才进一步拆分普通混合组；双语静态样式不会仅因互相重叠就被拆成弹幕。整体复杂度 O(n log n)，只在加载时分析，绘制时复用结果。

容器文本先通过 FFmpeg 解码成保留 ASS 样式头与事件覆盖标签的文本，再使用同一分类器。原始 ASS 的画布、运动和动画得以保留；其他字幕解码器合成的默认 ASS 位置不会被当成源空间证据。容器轨道在后台依次分析，完成后按逻辑轨加入菜单，保留解码期间用户的分类和关闭状态。

诊断命令：

```powershell
build/out/runtime/BilibiliBehaviors.Tests.exe --classify-caption path/to/file.ass
build/out/runtime/BilibiliBehaviors.Tests.exe --caption-inspect path/to/media.mkv
```

输出每组类别、事件数与自动评分／置信度／主要证据。回归样本涵盖真实 dan-any 默认 zstd／Base16384 导出、gzip／brotli、旧版 Raw、损坏及冲突数据、未输出记录隔离、实际 libass 像素对照、真实 DanmakuFactory 导出后再导入、静态／水平移动 SP、未知／同名非 DF 样式、混合 ASS、容器轨道、双语、顺序 SRT、密集评论、稀疏／推断时长、无效标签及 100000 条事件。
