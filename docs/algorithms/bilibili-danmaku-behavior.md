# B 站网页端弹幕时间与排布行为

本文记录 2026-10-25 对 B 站公开网页播放器的核对结果，用于区分数据源行为与客户端算法。结论限定于所检查的版本，不代表所有客户端或服务器实现。

- [播放器适配组件](https://s1.hdslb.com/bfs/static/player/main/widgets/npd.505.2d76eed1.js)：设置映射与弹幕模式适配。

## 同文弹幕同时出现

样本中，同文同时间的弹幕在服务端响应里已经存在：一组 14 条滚动弹幕的 `progress` 均为 `21674` 毫秒，另一组 13 条固定弹幕均为 `16870` 毫秒。并非仅有秒级精度导致的巧合。

将分段接口 `x/v2/dm/wbi/web/seg.so` 的记录与网页弹幕数据库按弹幕 ID 匹配：本次响应有 1,346 条，已加载数据库有 1,344 条，匹配的 1,344 条时间全部一致。两个旧 XML 入口各返回 600 条，其中与网页匹配的 598 条时间也全部一致。不同入口的条数不能直接当作网页端丢弃数量。

普通解析器只将输入时间由毫秒转换成秒。用三个内容相同、输入时间为 `10000 / 10050 / 10600` 毫秒的独立测试对象调用该解析器，输出仍分别是 `10 / 10.05 / 10.6` 秒。普通渲染模型按每条弹幕自己的时间计算初始位置，所检查的路径没有按相同文字将它们统一改时。

因此，这个样本的同文齐发在到达网页渲染层前就已经确定。公开前端和下发数据不能证明这些时间最初是如何形成的：可能涉及服务端处理，也可能来自发送端或原始记录；不能由此编造服务器的时间窗、文本归一化或聚类规则。相同文字在样本中也存在大量不同时间的记录，不是全部统一合并。

## 密度、重叠与碰撞

100% 显示区域下，普通弹幕的设置关系为：

| 密度 | 智能筛选门槛 | 组件内部区域值 | 常规碰撞行为 |
| --- | --- | --- | --- |
| 正常 | `abs(weight) >= 3` | `100` | 通常在第一组内寻找可用位置 |
| 较多 | `abs(weight) >= 2` | `100` | 放宽筛选，通常仍在第一组内排布 |
| 重叠 | `abs(weight) >= 2` | `0` | 可继续尝试第二、第三组；组间允许重叠 |

这里的内部区域 `0` 表示解除单组的区域限制，不表示屏幕高度为零。区域小于 100% 时，智能筛选门槛回到 3。无权重记录不会因为 `abs(undefined) < threshold` 被过滤。

重叠模式最多尝试索引 `0 / 1 / 2` 三组，每组内部仍检查碰撞。它不是无限增加图层，也不是完全跳过碰撞。滚动／逆向、顶部固定、底部固定使用不同的碰撞池。

滚动排布会比较文字包围盒、前一条右缘、预计离场时间与本条到达时间；纵向位置按实际文字高度寻找空隙，而非只使用等高行。空间不足时可拒绝本条，不保证所有输入都能显示。

## 滚动时长与速度

网页没有对所有窗口统一使用一个固定的穿屏时长。基础时长由容器宽度和文字宽度共同计算：先按宽度档位选取时长范围，再根据文字宽度与容器宽度之比进行非线性调整。

| 容器宽度 W（CSS 像素） | 最短／最长基础时长（秒） |
| --- | --- |
| 558 ≤ W ≤ 888 | 7 / 13 |
| 888 < W ≤ 1082 | 8 / 14 |
| 1082 < W ≤ 1246 | 9 / 14 |
| 1246 < W ≤ 1452 | 10 / 15 |
| 1452 < W ≤ 1744 | 11 / 16 |
| 1744 < W ≤ 2314 | 13 / 18 |
| 2314 < W ≤ 2560 | 14 / 20 |
| W > 2560 | 16 / 22，两端再加 `floor((W - 2560) / 500)` |

小于 558 像素或无法取得文字／容器宽度时，回退到配置时长，默认 4.5 秒。表格保留所检查脚本的实际分支，包括 2560 像素之后切换区间的行为。

计算后的速度还乘以用户速度设置；打开速度同步时，再乘以视频倍率。文字出入场带有额外安全距离，实际从创建到销毁的时长不能直接等同于基础时长。

## 其他确认的处理

| 处理 | 所检查版本的行为 |
| --- | --- |
| 提前准备 | 默认预读未来约 1 秒的弹幕，依据每条原始时间计算位置偏移，减少调度延迟。提前读取不等于按相同文字改时。 |
| 数量限制与优先级 | 区域限制还参与滚动批次的数量限制；高赞弹幕可优先进入碰撞检查。部分本人发送、高赞、特殊池弹幕存在容量／区域规则例外，并非所有弹幕完全同等处理。 |
| 过滤 | 云端权重门槛、关键词、正则、用户屏蔽、类型／颜色过滤和举报规则分别判断。“智能筛选”不等于前端现场运行文本语义模型。 |
| 随屏幕缩放 | 字号按容器高度分段计算，不是简单的高度同比缩放；关闭该设置时按源字号乘字号百分比。 |
| 连击计数 | `Combo` 是单独的互动模式，带计数、持续时间和资源。同文实时弹幕可增加其计数；它不是普通弹幕的通用同文齐发算法。 |
| 人物防挡 | 播放器读取服务端提供的 `mask_url`、帧率和遮罩数据，将遮罩映射到视频坐标。所检查路径不支持“网页实时自行推断所有人物轮廓”的结论。 |
| 内置特效模式 | 烟花、旋转、图片、渐变、双向等有独立模型与参数；不应将它们全部归为普通弹幕排布或 ASS 脚本效果。 |

## 对本项目的含义

- 保留原始时间与重复记录，使数据源已有的齐发组自然同时入场。缺少证据时不额外将相近同文弹幕吸附到同一时间。
- 普通弹幕已采用最多三组、组内防碰撞的重叠模型；纵向候选同时覆盖画布与现有文字包围盒边缘，并保持同负载位置打散，避免按入场顺序形成斜列。
- 普通滚动弹幕已采用按逻辑画面宽度与文字宽度计算的基础时长曲线，固定弹幕使用独立的 4.5 秒时长；入场时捕获时长、样式、运动时钟与分组，后续设置变化不重算已有实例。
- 启用随屏幕缩放时采用分段高度曲线，同时保留来源相对字号与自定义字号百分比；默认仍关闭。连击、人物遮罩和平台特效单独规划。
- 若未来为没有对齐时间的数据设计本地同文聚类，应明确作为本项目策略，保留原始时间并单独评估延迟、短词误合并和滚动／固定模式差异，不能称为已复现 B 站服务端算法。
